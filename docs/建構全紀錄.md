**## 7 個 AI Agent（核心）**

| Agent | 中文名 | 職責 | Temp | Max Tokens | 工作流位置 |

|---|---|---|---|---|---|

| ****The Profiler**** | 風格分析師 | 從上傳的作品提取「風格特徵 JSON 面板」 | 0.3 | 3000 | 上傳作品後手動觸發 |

| ****The Weaver**** | 情節編織者 | 根據 direction + 全部上下文寫章節草稿 | 0.8 | 4000 | 生成階段 |

| ****The Stylist**** | 風格校正師 | 審查風格匹配度 + 修訂 | 0.2 | 2500 | Weaver 之後 |

| ****The Extractor**** | 情報提取官 | 從定稿提取新角色/地點/世界規則/伏筆/章節摘要 | 0.1 | 3000 | finalize 時 |

**### Editor Analyst 偏好學習機制**

- ***入口****：finalize 時計算 `compute_diff(draft, final)` → `{similarity:SequenceMatcher.ratio(), magnitude: none(≥0.995) | minor(≥0.85) | moderate(≥0.55) | major, diff_text: 限 6000 字的 unified diff（只取 +/- 行）}`
- ***跳過條件****：magnitude == "none"
- ***學習****：feed 既有 profile + diff 給 LLM → LLM 返回合併後的完整 profile
- ***Profile shape****：`{rules:[{category(對話/遣詞/句式/節奏/描寫/情節/視角/語氣/其他), directive, strength(1-5), example}], summary, chapters_analyzed, last_chapter}`
- ***Strength 語意****：重複 +1（上限 5）、新規則 = 1、被推翻 -1（0 即淘汰）；最多保留 12 條
- ***注入****：`format_for_prompt(prefs, min_strength=2)` → `- [類別] directive ★★★`

**## 工作流 V3.2（核心邏輯）**

```python

async def execute(chapter, project_id, ...):

chapter.status = DRAFTING; commit

# 收集上下文

project = ...

style_profile = ...

plot_context = await hybrid_search_plot(project_id, direction, top_k=5)  # vector+BM25+rerank

style_examples = await hybrid_search_style(...)

previous_ending = last 2000 chars of prev chapter

previous_chapters_summary = chapter_summary + top-3 plot_milestones / chapter

# Weaver 寫稿

writing_preferences = EditorAnalyst.format_for_prompt(project.writing_preferences)

write_result = await Weaver.write(direction, style_features, style_examples,

plot_context, story_outline, previous_ending,

character_cards, world_settings,

previous_chapters_summary, writing_preferences)

draft = write_result["content"]

# 空內容防護

if not draft.strip():

chapter.status = OUTLINE; chapter.draft_content = None; commit; return

# ⭐ 立即保存 draft（之前 ordering bug 的修復）

chapter.draft_content = draft

chapter.status = REVIEW; commit

# Review + revision（包 try/except，non-fatal）

try:

logic_review = await Chronicler.review(draft, ...)

if style_profile: style_review = await Stylist.review(draft, ...)

# 最多 2 輪 revision

while needs_revision and revision_count < 2:

...

except Exception as e:

logger.warning(f"Review failed (non-fatal): {e}")

# 最終保存

chapter.draft_content = draft  # 可能被 stylist 改過

chapter.final_content = direction + "\n\n" + draft

chapter.status = REVIEW

commit

async def finalize(chapter, project):

final = chapter.final_content or chapter.draft_content

# 1. Extractor（non-fatal）

try:

extraction = await Extractor.extract(final, project.outline, character_cards, world_settings, chapter_number)

chapter.extraction_result = extraction

merge into project.character_cards / world_settings / outline

flag_modified(project, ...)

except: ...

# 2. 索引到 plot_chunks（non-fatal）

try:

chunks = chunk_text(final, chunk_size=500)

await VectorStore.index_plot_chunks(project_id, chapter.id, chunks)

except: ...

# 3. Foreseer（non-fatal）

try:

suggestion = await Foreseer.plan_next(final, chapter_number, ...)

chapter.next_chapter_suggestion = suggestion

except: ...

# 4. Editor Analyst（non-fatal）

try:

if draft and final and draft.strip() != final.strip():

diff_info = compute_diff(draft, final)

if diff_info["magnitude"] != "none":

updated = await EditorAnalyst.learn(draft, final, project.writing_preferences,

chapter_number, diff_info)

if updated:

project.writing_preferences = updated

flag_modified(project, "writing_preferences")

except: ...

# 5. 完成

chapter.status = FINALIZED; commit

```

- ***關鍵設計****：所有非核心步驟（Extractor/Foreseer/Analyst/Index）都是 non-fatal，包 try/except，不影響定稿成功。

**## 混合檢索流程（Hybrid Retrieval）**

```python

async def search_plot(project_id, query, top_k=5):

# 1. Vector recall (top 20)

q_emb = await embed_query(query)  # DashScope text-embedding-v3

vector_rows = SELECT * FROM plot_chunks WHERE project_id=:pid

ORDER BY embedding <=> :q_emb LIMIT 20

# 2. BM25 recall (top 20)

q_tokens = "|".join(jieba.cut(query))  # OR query for recall breadth

bm25_rows = SELECT *, ts_rank_cd(to_tsvector('simple', tokens), to_tsquery(:qt)) as rank

FROM plot_chunks WHERE project_id=:pid

AND to_tsvector('simple', tokens) @@ to_tsquery(:qt)

ORDER BY rank DESC LIMIT 20

# 3. RRF fusion (rrf_k=60, dedup by id)

fused = rrf_fuse(vector_rows, bm25_rows, rrf_k=60)

# 4. Rerank (qwen3-rerank, non-fatal)

try:

ranked = await rerank(query, [r.content for r in fused], top_n=top_k)

return reorder by ranked

except:

return fused[:top_k]  # fallback to RRF order

```

- ***注意****：
- pgvector 不能 ALTER 維度，必須 `DROP COLUMN embedding; ADD COLUMN embedding vector(1024)`
- BM25 須 `tokens` Text 欄位 + GIN index on `to_tsvector('simple', coalesce(tokens,''))`
- 'simple' 配置 = 純 token 匹配無詞幹處理（適合中文 jieba 結果）

**## 文件解析（DocumentParserService）**

統一入口 `parse_file(content, filename)`，副檔名分派：

- ***`.epub`***：`ebooklib.read_epub` 不接 BytesIO，要 `tempfile.mkstemp(suffix=".epub")` 寫實體檔再讀，讀完 `os.unlink`
- ***`.txt`***：UTF-8 解碼，視為單章
- ***`.pdf`***：PyPDF2 逐頁提取，按 `第X章/Chapter X/數字.` 模式分章，無標記則整本視為一章
- ***chunk_text(chunks, chunk_size=500, overlap=50)****：必須對單段 > chunk_size 的硬分割（否則 embedding 8192 token 限制會 400）。
- ***embedding sanitize****：
- 空字串 → 替換為 `"（空白段落）"`
- 超 6000 字元 → 截斷
- 失敗時 `logger.error(resp.status_code, resp.text[:500])` 再 raise

**## 已踩過的坑（必看）**

1. ****bcrypt/passlib 在新版 Python 經常壞**** → 改用 `hashlib.pbkdf2_hmac("sha256", pw.encode(), salt.encode(), 100000)` + `secrets.token_hex(16)` 鹽

2. ****pgvector 維度變更****：不能 ALTER，必須 DROP + ADD COLUMN，所以舊向量會丟，須從保留的 `content` Text 重新 embed

3. ****DashScope rerank 端點易混淆****：必須 `compatible-api/v1/reranks`（不是 `compatible-mode`），其他 API 用 `compatible-mode/v1`

4. ****DashScope embedding 限制****：單筆 input 上限 8192 tokens；中文約 1 char = 1-2 token，安全截 6000 字元

5. ****LLM JSON 解析脆弱性****（Foreseer/Extractor 都會遇到）：寫 robust parser

- strip 代碼柵欄 `re.search(r"```(?:json)?\s*(.+?)```", s, re.DOTALL)`

- 取最外層 `{...}`：`s[s.find("{"):s.rfind("}")+1]`

- 修復候選：全角引號 → ASCII（`re.sub(r'”(\s*[,}\]:])', r'"\1', s)`）+ 多餘 `""` collapse + 移除尾隨逗號

- 嘗試 `json.loads(cand, strict=False)` 允許未轉義控制字元

6. ****Workflow ordering bug****：必須 Weaver 完成立即保存 `draft_content` + commit，再做 review；不能等 review 跑完才寫 draft，否則 review 失敗會留下 status=REVIEW 但 draft 為空的章節

7. ****JSONB 修改不持久化****：Python 改 dict 後須 `flag_modified(obj, col)` 否則 SQLAlchemy 不檢測變更

8. ****dict.get(k, "") 陷阱****：當 key 存在但值為 None 時返回 None，後續 `len(None)` TypeError；改用 `dict.get(k) or ""`

9. ****agent ↔ services 循環 import****：`from app.agents.weaver import WeaverAgent` 直接 import 會循環，測試 agent 一律走 API E2E 或在 docker exec heredoc 中內聯 helper body

10. ****prompt 上下文截斷是隱形 bug****：DB 有資料 ≠ Agent 看得到。每個 agent 內部 truncate slice 都要審計，新欄位要確認真的傳成參數

11. ****EPUB ebooklib 不接 BytesIO****：新版做 `os.path.isdir` 檢查；必須 tempfile 寫實體檔

12. ****per-agent 設定 base_url 但忘了填 api_key****：fallback 到 .env 的 key，但 .env 可能是不同端點的，導致 401；UI 須在每個 agent 都暴露 api_key 輸入框

13. ****保存設定時前端強制要求重新填 api_key****：應放寬，後端也要保留舊值（不要因空字串覆蓋）

14. ****`docker exec` heredoc 必須加 `-i`****：否則 stdin 被忽略，腳本不執行但 exit 0

15. ****AsyncSessionLocal 不是 async_session****：app/database.py 裡正確的 session factory 名稱

16. ****frontend dev 模式有 volume mount `./frontend/src:/app/src`****：改前端代碼會熱重載，無需 rebuild；後端則是每次改都要 rebuild（~2 分鐘）

17. ****刪除有 FK cascade****：`DELETE plot_chunks WHERE chapter_id IN (...)` 必須在刪 chapter/project 之前執行

18. ****DELETE 路由衝突****：`/projects/{id}/writing-preferences` 必須註冊在 `/projects/{id}` 之前，否則 path 衝撞

19. ****新角色引入靠 prompt 規則 + Foreseer schema 雙管齊下****：Weaver SYSTEM_PROMPT 加規則第 10 條 + Foreseer JSON 加 `new_characters` 欄位

20. ****章節創建支援兩種模式****：`ChapterCreate.user_content` 可選；有值則直接設 status=REVIEW + draft/final_content，跳過 AI；沒值則 status=OUTLINE 等用戶按生成

**## 實作順序建議**

1. 建專案目錄 + `requirements.txt` + `package.json` + `docker-compose.yml`

2. 後端 models / schemas / database.py / main.py（先空殼）

3. `LLMService.from_user_settings`（per-agent 解析）

4. `embedding_service.py`（embed_texts/embed_query/rerank，sanitize）

5. `vector_store.py`（hybrid search：vector + BM25 + RRF + rerank）

6. `epub_parser.py` → `DocumentParserService`（epub/txt/pdf + chunk_text 硬分割）

7. 7 個 agent 一個一個寫，每個都用 `from_user_settings(llm_settings, agent_name=...)`

8. `workflow.py`：execute（含 ordering 修復 + non-fatal review）+ finalize（4 step non-fatal）

9. API 路由（auth/projects/chapters/styles）

10. 前端：api.ts → store.ts → 頁面（landing → login → dashboard → settings → styles → projects/[id]）

11. Docker 編排，`docker compose up -d --build` 啟動驗證

12. 創 test user，註冊 → 創 project → 創 chapter direction → generate → edit → finalize → 看 outline/character_cards 自動更新 + 下章建議生成

**## 驗收標準**

- `docker compose up -d` 全部健康，4 服務起來
- http://localhost:3000 可註冊登入
- 創 project，加 chapter（direction），生成 → 草稿出現
- 編輯定稿後：outline 自動加 `### 第 N 章 — Title [已完成]`、character_cards 新增、world_settings 累積、next_chapter_suggestion 顯示 2-3 條分支（含新角色提示）
- Settings 頁面可為每個 Agent 設獨立 model/Base URL/API Key
- 上傳 EPUB/TXT/PDF 都能成功切片入庫
- 編輯草稿後定稿，再生成下一章時，prompt 包含「作者的個人寫作偏好」段落（檢查方式：DB select `projects.writing_preferences`）
- 生成中/定稿中按鈕有 spinner 不會看起來無反應
- 北京端點 + 國際端點混用各自 key 都能正常工作

- ***這是一個用「雙軌向量庫 + 7 Agent + V3.2 三階段工作流（生成→審核→定稿觸發提取/規劃/學習）」搭起來的、能持續從用戶編輯行為自我進化的中文長篇小說 AI 寫作平台。核心 trick 在於把所有非主流程（提取、預測、學習）做成 finalize 時的 non-fatal pipeline，並透過 in-context 注入學到的偏好實現「越寫越好」。****
